# decode-prefill-consistency / v1

Does the engine compute the same next-token distribution when it decodes a token as when it re-reads the same tokens in
one prefill? A decode-only defect (for example attention that skips recent tokens) shows up as disagreement.

**Server:** prefix caching off, so `prompt_logprobs` scores every position. Speculation off unless the configuration
says otherwise; with speculation on, the generated tokens pass through the draft-and-verify path, and their decode
distributions are compared with prefill the same way. Concurrency 1.
**Prompts:** GPQA Diamond doc ids 0-5 (runs of 2026-10-07) or 0-11 (later runs; each run's notes list them) under
`gpqa-diamond/v1` rendering (the lm-eval chat messages through the served
chat template, thinking on). Prompt token ids are not published; they are regenerated from the dataset.
**Per prompt:**
1. Generate 2,600 tokens: temperature 1.0, top_p 1.0, `seed` 1234 + doc id, `logprobs` 20, `ignore_eos`, token ids
   returned, so every trace crosses 2,048 tokens of context.
2. Re-score the same token ids by prefill with `prompt_logprobs` 20: the first 2,048 ids for positions below 2,048
   (short-prefill path), the whole sequence for positions from 2,048.
3. For each generated position `i` (the decode step whose causal length is `i`), compare decode with prefill:
   `abs_dlp` = |difference in log-probability of the sampled token|; `top1_agree` = same top-1 token;
   `kl_top20` = KL(prefill ‖ decode) over the top-20 tokens both return, each renormalised (null if fewer than 2 shared).
**Regions:** `lt2044` (i < 2,044), `2044-2047`, `ge2048`; each split by `i mod 4` (`mod4`).
**Summary:** per region and per region|mod4: positions, mean `abs_dlp`, `top1_agree` share, mean `kl_top20`.

Decode and prefill use different kernels in any engine, so agreement is never exact; the measure is comparative
(same configuration with and without a change). The two configurations sample different continuations after their
first disagreement, so positions are matched by index, not by text. **Noise floor:** a run is one generation per prompt,
and the engine is not bitwise reproducible even one request at a time, so two runs of one configuration with the same
seeds differ (`comparisons/glm53-flash-v091-decode-prefill-repeat`: region means up to about 2x apart, single prompts up
to about 6x). Compare a difference with that spread, and use prompts 0-5 when comparing with the 2026-10-07 runs.
Client: `tools/clients/decode_prefill_consistency.py`.
