# decode-prefill-consistency / v2

v1 at 16,000 generated tokens instead of 2,600, with positions also summarised in context-length bins. Everything not
stated here is as in [v1](v1.md): server settings, sampling, seeds, re-scoring, the three measures and the rows.
Added 2026-10-10 for the completion investigation (`investigations/2026-10-glm53-completion`, PLAN.md amendment 4).
v1 is unchanged.

**Prompts:** GPQA Diamond doc ids 0-5 (each run's notes list them).
**Per prompt:** generate 16,000 tokens (`ignore_eos`), then re-score as in v1: the first 2,048 ids by prefill for
positions below 2,048, the whole sequence for positions from 2,048. The server's chunked prefill (2,048 batched tokens in
the configurations measured so far) processes a long re-score in chunks, so from 2,048 the reference is itself chunked
prefill over cached context, at any length.
**Rows:** as v1 (`doc_id`, `i`, `mod4`, `region`, `abs_dlp`, `top1_agree`, `kl_top20`). `i` is the causal length, so it
includes the prompt (124-365 tokens for doc ids 0-5): positions run to about 16,100-16,400.
**Summary:** v1's `by_region`, plus `by_bin` over `i`: `0-2043`, `2048-7999`, `8000-15999`, and `ge16000` (the last
few hundred positions of each prompt; outside the three bins named in amendment 4 and reported separately). Positions
2,044-2,047 are in no bin, as in v1.

The noise floor of v1 applies: a run is one generation per prompt, and two runs of one configuration with the same seeds
differ. With 6 prompts, a bin's mean rests on fewer prompts than the 12-prompt v1 runs.
Client: `tools/clients/decode_prefill_consistency.py` with `--n 16000`.
