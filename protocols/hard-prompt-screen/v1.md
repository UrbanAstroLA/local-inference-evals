# hard-prompt-screen / v1

> **Withdrawn as a rate measure (2026-10-09).** Every repeat sent request seed 1234. The engine draws its sampling noise
> from the seed, so all repeats of a question drew on the same sampler noise. Their texts diverge early (batching changes
> the arithmetic), so the repeats did vary, but that variation is not statistically meaningful. Only repeat 1 of each
> question is published, for each configuration's first screen; it shows that loops or exhaustion occur, not how often.
> Failure rates, intervals and comparisons made with this protocol were withdrawn (notice and evidence:
> `investigations/2026-10-glm53-looping`). Successor: `hard-prompt-screen/v2`.

A screen for non-completion (loops and exhaustion) on long reasoning.

**Items:** GPQA Diamond doc ids 79, 13, 127, 88, 121 under `gpqa-diamond/v1` prompt rendering (every one produced an
empty answer in earlier full runs), 8 repeats each = 40 requests. Prompts are the lm-eval-rendered chat messages;
`prompt_hash` is recorded so the exact prompt can be verified.
**Sampling:** temperature 1.0, top_p 0.95, `seed` 1234 on every request, max_tokens 327,680, thinking on, streaming.
**Schedule:** 8 concurrent, order fixed by `random.Random(7).shuffle` over (doc, repeat) pairs.
**Early stop:** from 30,000 reasoning characters, every 10,000 new characters, compute the zlib compression ratio of
the last 30,000 characters; three consecutive values below 0.10 close the stream (class `loop`). Validated offline
on 80 earlier traces: stopped 27/28 loops, 0/44 completions, 0/8 exhaustions.
**Classes:** `ok` = finish reason `stop`; `loop` = stopped early, or finish `length` with tail zlib ratio < 0.15;
`exhaust` = finish `length` with ratio >= 0.15; `error` = transport or server error.

**v0** (2026-09-30 runs) is identical except it has no early stop.

**Other known limitations (recorded 2026-10-06).** Items were selected from one engine's failures (empty answers in the
tpurtell 0.8.0 GPQA runs). Outcomes cluster by item.
