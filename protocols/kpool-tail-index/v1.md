# kpool-tail-index / v1

Checks which tokens a DCP1 sparse-MLA decode step attends, using the engine image's own compiled Triton kernels on one
GPU, with no model loaded: the kpool expansion (`_expand_pools_and_append_tail_kernel` in
`models/glm5next/nvidia/ops/kpool_compress.py`), then, when present, the tail-compaction fix, then the positional mask
(`_mask_page_table_after_nsa_len` in `v1/attention/backends/mla/b12x_mla_sparse.py`), in the order of the DCP1
logical-id branch, with an identity block table.

**Inputs:** a single row per case. Pool selections of 4-token pools (512 slots, sliced to 511 as the indexer does):
- `packed`: the valid pools ahead of the -1 padding, shuffled among themselves (what the pool top-k is expected to emit);
- `scattered`: a synthetic worst case with valid pools and padding interleaved, where the 511-slot slice itself can cut
  a valid pool before any masking.
Causal lengths 5-8, 1001-1004, 2040-2052, 4097, 100003. Pool selections come from `random.Random(1234)`.

**Per case:** `nsa_len` (selection length after clamping), `selected` / `attended` token counts, the tail (the
incomplete newest pool: the current token and up to two before it), the tail columns (2044-2046) before and after the
mask, `tail_attended`, `n_dropped` (selected but not attended), `equals_dense_prefix` (for lengths up to 2,047: the
attended set is exactly tokens 0..L-1, the set the dense short-prefill path attends; null above), and a 16-hex-digit
SHA-256 prefix of the final index row, so rows can be compared across images byte for byte.
**Summary:** per layout: cases, cases where the tail is dropped, cases with any drop, tokens dropped.
Check: `tools/kernel/kpool_tail_index_check.py`.
